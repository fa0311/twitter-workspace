- **Declarative over procedural**: registries are typed literal definitions, not registration calls (twitter-snap's render definitions).
- **No needless backward compatibility**: when the live API dropped a field, drop the fallback after a live check ("無駄な後方互換性は利用者が混乱するだけ").
- **POST wherever X was seen using it**; the placeholder tool keeps POST when a recording used it.
- **Guest-token runs and recordings happen on instruction, not on a schedule**: no nightly guest job, `twitter-api-safe-dump` / `update-placeholder` are manual (workflow_dispatch) so a human checks before placeholder values change.
- **Schema sharing is a risk** ("共通化はそこそこリスクがある"): reuse a schema only for the same backend object under the same key; a look-alike site gets its own type; never widen a shared type for another site.
- **Enum policy** ("腕の見せ所"; "重要な部分は攻めて、内部のどうでもいい値はどうでもいい"): enum when the value decides shape or branching, or is user-facing and closed; plain string with known values in a comment for UI plumbing. twitter-snap is the reference consumer. Written in twitter-openapi `CONTRIBUTING.md`.
- **Relay and clients know nothing of each other**: the typed clients only document that the endpoint is configurable; the relay README carries the recipe.
- **GitHub Actions stay simple and readable**: one `jq` line over shell gymnastics; an action's own option over a hand-rolled check.
- **twitter-snap wraps text like a browser (UAX #14), no prettier**: phrase-level Japanese wrapping (BudouX / `word-break: auto-phrase`) was offered with sample images and declined ("不要", 2026-10-30). Images should break lines where X.com does.
- **A snapshot is not the web page** (2026-10-31: "Webを画像にするという都合上、全く同じUIにすることは出来ない。してしまうとあとから見返した時に見づらくなる"): the X reference theme copies x.com's type, colors, spacing and informative parts, but anything that only works on an interactive page (carousels that cut media off, relative times, controls such as mute / Grok / more / Rate it / share) is adapted or dropped so the image stays readable later.
- **Two premises for twitter-snap themes** (2026-10-31): the plain themes are read later and must not depend on when the snap was taken (no views, a running poll shows choices + end date, no page controls); the X reference theme may depend on the moment (views, counts, time left, mute / Grok / more / Rate it / share) and copies the web as far as it can. Both keep media complete: photos stacked at full width at their own proportions (master's layout, "画像の比率はツイートごとにかなり異なる"), videos one after another in one frame; x.com's carousel is not copied because media falls out of the picture ("致命的").
- **Dates in snapshots always carry the year** (2026-10-31, quoted tweets: "Oct 22, 2024 みたいな表示固定でいい、わかりにくい"): x.com drops the year inside the current year, twitter-snap does not, because the image is read later.
- **No helper whose semantics are debatable** (2026-10-31, `paginate()` PRs closed unmerged: "議論の余地があるなら実装しないほうが良い"): a cursor loop, its limit, rate-limit waiting and cancellation are the caller's responsibility; the wrappers expose the cursor and the rate-limit headers and stop there. Prefer no API over an API with arguable defaults.
- **twitter-snap README stays a list of one-line examples** (2026-10-31, "READMEいじる意味ある？ x.com reference theme の時も思った"): a feature gets `# comment` + command in the example block, nothing more. No explanatory paragraphs (they belong in the PR description), no per-feature sample images in `docs/img` (samples go to issue #47 by the maintainer, or to `screenshot/` for them to look at); the oclif usage block (`node replace.js`) documents the flags. The x.com reference / Thread / Translation sections were trimmed back to one line each (#99, #92, #93).
- **A list that grows without bound gets its own page** (2026-11-01, relay #40 dashboard: "Rate Limitは無限に増えていくだろうから、別のページに作ったほうが良いのでは？"): per-endpoint tables and similar open-ended data are not sidebar panels; give them a page (hash-routed view in the dashboard) with a filter.
- **No README section for transparent behaviour** (2026-11-01, relay #40 "Rate limits" section: "READMEの問題が残っている" → "Rate limitsの節いる？"): headers passed through unchanged, a debugging endpoint such as `/health`, or a panel that is visible in the UI get no README text; the PR description explains them. A README section needs something the user must do or know to use the feature.
- **No version numbers or "x and later" notes in READMEs** (2026-11-01, relay #41 recipe said "(0.1.5 and later)": "なんでバージョンとか書くかな？それはgitから確認できるでしょうに"): which release introduced an API is read from git / tags / the PR, never written into a README. Same spirit as the one-line README policy: say what the thing does, not its history.
- **Translation looks like x.com's translated post** (2026-10-31, "TwitterのtranslateのUIにもっとよせて"): the translation replaces the text (the original is not kept in the image), with the Grok-marked "Translated from <language>" line above it; the X reference theme also copies "Show original", the gear and the "Rate this translation" row, the plain themes keep only the line. Measured from the real page, not guessed. Both calls (original dropped, Grok mark in the plain themes) confirmed by the maintainer the same day ("どっちもLGTM").
- **TIAD**: avoid changes unless asked.
- **Feature ideas 2026-10-31**: the maintainer approved the idea list (twitter-snap poll / Community Notes rendering and thread mode, client pagination iterators and relay session helper, translation API after recording, MCP snap tool, relay rate-limit visibility, spec candidates from the relay catalog) and declined a catalog freshness check in CI (`recordedAt` age warning): not wanted. **X reference theme (approved 2026-10-31, "いいね！")**: a twitter-snap theme that reproduces the x.com tweet layout from measured values; it may share code with the existing themes and the existing themes' design may shift slightly as a result ("既存テーマと共通化してもいいよ、既存テーマのデザインが若干変わっても良い"). Translation, when it comes, takes the target language as an explicit argument (`--translate <lang>` style): X now renders in the viewer's translation language by default, so an implicit default would be ambiguous (2026-10-31).

**Why:** these settle recurring judgement calls so they are not re-asked.

**How to apply:** apply them silently; when a new judgement call appears, decide in their spirit and say so. Related: [[user-fa0311-preferences]], [[feedback-twitter-ecosystem-working-rules]].
- **Output format rule (2026-11-04, twitter-snap)**: the post decides still vs motion, the `-o` extension only picks the encoding. Formats that hold a still only (png, jpg, svg, pdf) give a still (non-png falls back to png); mp4 / webm hold motion only (a still becomes the 5 s loop); webp / gif hold both and follow the post (one frame or animated). Encoders come from a table in `src/utils/video.ts` and `--ffmpegAdditonalOption` is appended after it, so it still overrides. Animated images carry no sound track, so the audio filter chain is built only for containers that hold audio.
